# Переход NHP_IRD на Django и PostgreSQL

## Цель

Переход завершён: текущая версия проекта работает только на Django с PostgreSQL. Flask web, scheduler, маршруты, репозитории, конфигурация и Flask-зависимость удалены из дерева проекта. Старый Flask-коммит остаётся в истории Git; SQLite и архив файлов сохранены как data backup. Публичный адрес обслуживает Django через HTTPS ngrok с Basic Auth и обязательной Django-аутентификацией.

## Функциональное соответствие

- Проекты: список и напоминания, создание, редактирование, архивирование, восстановление и удаление.
- Документы: пакетные загрузки PDF/изображений, HEIC, OCR/AI и локальный fallback, фоновые задания, поля и заметки, привязка к комплектности, дубликаты, архив/восстановление, PDF/Word preview и просмотр страниц.
- Переписка и согласования: загрузка и извлечение реквизитов, редактирование, сроки, просмотр, скачивание и удаление.
- Комплектность: шаблоны и их копирование, состав, пункты проекта, статусы, документы с множественными связями, сроки, замена, архивные ссылки.
- Документы проекта: генерация описи, запроса, актов, история и скачивание актов, ZIP-экспорт с JSON, оригиналами и SHA-256 манифестом.
- Служебные задачи: Django worker и PostgreSQL-очередь; напоминания и уведомления переведены на Django ORM. Django scheduler включён после остановки Flask scheduler, SMTP настроен.
- Дополнительные функции: стадия проекта, записная книжка с очисткой HTML и расширенный каталог комплектности.
- Защита: обязательный вход для портала и Django Admin, отдельный суперпользователь, HTTPS через ngrok, Basic Auth на туннеле, CSRF middleware, проверка принадлежности объектов проекту, файловых путей и типов/размеров загрузки.

## Архитектура и данные

- Django URL dispatcher и views находятся в `django_site/` и `migration_portal/`; в runtime нет Flask application factory, контекста или URL map.
- Данные Django хранятся в отдельном PostgreSQL 16 volume. Модели и миграции покрывают рабочие таблицы; команда `import_legacy_sqlite` читает SQLite только для чтения и проверяет содержимое перед записью.
- Команда `audit_legacy_sqlite` в режиме только чтения сравнивает все 11 таблиц построчно, показывает SHA-256 каждой таблицы и ключи недостающих, лишних или изменённых записей.
- Файлы проекта находятся в `uploads` и `instance/acts`; каталоги смонтированы в Django-контейнеры.
- Корневой `Dockerfile`, `docker-compose.yml` и `requirements.txt` запускают Django; Flask-зависимостей и старых Docker entrypoint нет.
- Django web доступен на `127.0.0.1:5050`, PostgreSQL — на `127.0.0.1:5438`. ngrok использует зарезервированный домен `puling-enoch-inequilaterally.ngrok-free.dev`.
- Финальный импорт выполнил `import_legacy_sqlite --replace`: 197 строк в 11 таблицах; `audit_legacy_sqlite` подтвердил точное совпадение всех строк и SHA-256 на момент cutover. С тех пор Django записал новые строки в PostgreSQL; SQLite оставлена как архивный снимок и не должна повторно импортироваться.
- Резервные копии перед переключением сохранены в `instance/backups/django-cutover-20261119T092251Z/`: SQLite, dump PostgreSQL и архив файлов.

## Проверки

Проверены PostgreSQL data import и row-level audit, `manage.py check`, отсутствие изменений схемы без миграций, 25 Django функциональных тестов с CSRF и внешний вход через HTTPS ngrok. Локальные проверки:

```bash
.venv-django/bin/python manage.py check
.venv-django/bin/python manage.py makemigrations --check --dry-run
.venv-django/bin/python manage.py test migration_portal
```

## Состояние данных и обслуживание

Импорт завершён, а PostgreSQL теперь содержит новые данные, которых нет в SQLite-снимке. Не выполнять повторный импорт `--replace` поверх действующей базы. Команда `audit_legacy_sqlite` остаётся только для read-only проверки исходного импорта; расхождения по новым Django-записям ожидаемы.

Архивная SQLite сохранена только как резервный снимок. Для обслуживания
используйте регулярные резервные копии PostgreSQL и файлов. Не запускайте
`import_legacy_sqlite --replace`: это может удалить данные, добавленные после
перехода. Read-only аудит исходного снимка доступен отдельно:

```bash
docker compose exec django-web python manage.py audit_legacy_sqlite \
  --source /app/instance/documents.db
```
